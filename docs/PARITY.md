## Expected differences (deliberate decisions)

- **User and practice ids are UUIDs.** Legacy used 24-hex ObjectIds. The frontend treats them as opaque strings; the parity check masks every id. Stuck query ids keep the 24-hex ObjectId form (the frontend routes and E2E tests expect it).
- **C++ check on AI code.** A malformed program is asked for once more, then stored with `code: null` (legacy passed it through). The fake AI answers valid C++, so no step shows it.
- **Fail-fast configuration.** Every variable (including JWT_EXPIRES_IN and SYNC_CRON) is checked at startup; legacy failed some of them on first use. Not visible through the API.
- **Numbers.** Jackson writes whole doubles as `1.0` / `0.0` where JS wrote `1` / `0`; both parse to the same number.
- **Error Content-Type.** `application/json` instead of `application/json; charset=utf-8` (headers are not compared).

Value differences explained by those decisions:

- **stuck AI outage (tied neighbors)** — Its text-search neighbors tie in textScore (6+ problems at 0.5714); the legacy database returned ties in arbitrary order (legacy gave different topics across runs), Spring breaks ties by problem id. Scores themselves match.
